# Essai complet de toutes les features — 2026-10-24

État de `main` après la PR #87 (A2 et T5), essayé de bout en bout avec le
vrai modèle pour vérifier que les features fonctionnent **ensemble**. Essais
précédents : [2026-10-13](essai-2026-10-13.md), [2026-10-14](essai-2026-10-14.md).

## Machine et méthode

- **Modèle** : `qwen3-coder:30b` et `bge-m3` sur un pod RunPod neuf (GPU de
  24 Go), par le proxy HTTP de RunPod. L'adresse du pod n'est pas dans le dépôt.
- **Client** : poste Linux (Intel i7-1355U, 12 cœurs, 14 Go de RAM),
  Python 3.12, Docker local pour les sandboxes.
- **Méthode** : un script pilote le **vrai CLI** `sensai` (sous-processus,
  réponses « y » aux confirmations) dans un projet jetable : `calcul.py`
  (faute de frappe), `stats.py` (bug sur les négatifs), `texte.py`,
  `reglages.py` (clé d'API factice), `README.md`, un PDF d'une page et un
  schéma JSON. Puis le **vrai serveur web** (`sensai-web`) par son API HTTP.
  Dossiers de données jetables ; `~/.sensai` non touché.
- Une mesure par scénario : des ordres de grandeur.

## Limites

- Une mesure par scénario, un seul modèle, un seul réseau.
- Le serveur web est essayé par son API, pas par l'interface dans un
  navigateur ; l'affichage des relais d'agents et des outils MCP y reste
  simulé.
- Le client MCP n'est pas encore essayé avec un serveur MCP publié (seulement
  le serveur de test du dépôt).

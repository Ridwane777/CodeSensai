### T3: two problems found
`sensai-browser` image built the same day (Chromium 155, Debian 12, 297 MB).

1. **Chromium returns nothing.** With the settings in `browser_sandbox.py`,
   the `--dump-dom` output is empty (0 bytes), and the tool answers
   `SearchUnavailable`. Removing one setting at a time, the cause is the
   `--blink-settings=scriptEnabled=false` option: without it, the page
   arrives (14 KB). JavaScript stays off through the image policy
   (`"JavascriptEnabled": false`), so the option seems redundant. To be
   confirmed by Workstream B, which tests for its presence
   (`tests/execution/sandbox/test_browser_sandbox.py:69`).
2. **DuckDuckGo blocks the browser.** Without that option, the page received
   is the anti-bot wall (`SearchBlocked`), whereas the same request made from
   the machine with `curl` returns 10 results. Headless Chromium probably
   announces itself as `HeadlessChrome`: a lead to check (change the user
   agent), with no guarantee, since the engine can change its rules.

Workstream B code was not modified during the trial.

# Trial 2026-11-02: the whole scenario in one take (web)

**Machine**: RunPod pod (GPU), `qwen3-coder:30b` and `bge-m3` served by Ollama;
`sensai-web` launched on a throwaway demo project (`stats.py`, its tests with
one failing `test_mediane`, `deploiement.txt` holding a fake AWS key
`AKIA…EXAMPLE`, few-shot examples, `config.json` with the cache, share links,
the MCP test server and two personas "Sensai" and "Reviewer Sensai" with
`write_file` and `run_code` disabled). The pod address is not in the repository.

**Method**: steps S0 to S9 of the [scenario](../../design/persona-and-scenario.md),
driven by a Playwright script in the browser, real model answers, nothing
staged. Recorded in three parts (the recorder was stopped by mistake after
S7, then once more before S9 d) and assembled into
[demo-day-in-the-life.webm](../../demo/web/demo-day-in-the-life.webm)
(6 min 30, idle frames removed).

## What was seen

| Step | Result |
| --- | --- |

| S7 EV2 | the AWS key shown as `[REDACTED:aws_access_key]`; the injection message blocked before the model |

| S9 a `schedule_task` | task created from the conversation, visible on the Planning page |
| S9 b–c export, journal, quality | export, journal, evaluation of the last answer, attacks replayed |
| S9 d persona | "Reviewer Sensai" active: asked to write the file, it gave the code but **did not write it** and said it could not |

## Issues found

- In S9 a, the model also called `update_state` twice without being asked
  (backlog #22).
- The take had to be split in three; the assembled video is continuous per
  step but not one single run of the server process for S9 d (new
  conversation).

The qwen3:8b measurement on the team's laptop was made the same day
([generation parameters](../generation-parameters.md)).

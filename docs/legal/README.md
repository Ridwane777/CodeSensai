# Legal file — risk analysis

> **Disclaimer.** These documents are written by the student team for what
> the project is today: a development tool used by the team on its own
> machines, with a command-line interface and a local web interface
> (`sensai-web`), and no public online service. They do not replace a
> lawyer's advice. To be reviewed if the project is put online or used by
> third parties.

## What CodeSensei is, from a legal point of view

- A development assistant that runs **on the user's machine** (CLI, or the
  local web server `sensai-web`, bound to `127.0.0.1` by default) and sends
  its messages to a language model served by **Ollama**: either locally, or
  on a **GPU pod rented from RunPod**
  ([ADR-0004](../decisions/0004-modele-et-infrastructure.md)).
- It can **run code** generated by the model (Docker sandbox, T2), **read
  and write files** in the current folder (T4), **search the web** (T3),
  **work unattended** at intervals (X5) and **keep the conversation
  history** on disk (M1).
- Since 2026-10-29 the web interface can also **create share links**
  (read-only copy of a conversation, X3,
  [ADR-0048](../decisions/0048-share-links.md)), **delete a
  conversation**, and **attach text files** to a message.
- **No accounts, no payment, no advertising, no public website.**

## Risk analysis

| # | Risk | Reference text | Measure in place | Status |
| --- | --- | --- | --- | --- |
| L1 | **Personal data sent to the remote model.** A message (and, with M1, the whole history of the resumed session) goes to the RunPod pod. It may contain names, e-mails, client code. | GDPR art. 5 (minimisation), art. 28 (processor), art. 44 ff. (transfers outside the EU) | The model can run locally (`--host` defaults to `localhost`). `--new-session` option to avoid resending the history. | ⚠️ **Partial.** RunPod claims GDPR compliance only for its **European regions**. The region and cloud type (Community or Secure) of the team's pod are **to be checked and written down** here. |
| L2 | **Ollama pod open to everyone.** Ollama has no authentication: a pod exposed on the Internet is an open generation API, usable by anyone on our credit. | GDPR art. 32 (security of processing) | None yet. | ❌ **Open.** ClickUp task "Protéger l'accès au serveur de modèle distant" (Lot D), late. Possible fixes: SSH tunnel, proxy with a token, firewall on the team's IP. |
| L3 | **Secrets pasted into the conversation** (API key, password) stored in clear on disk and sent to the model. | GDPR art. 32; security good practice | M1 files in mode `600`, purge after 30 days ([donnees-locales.md](donnees-locales.md)). Since 2026-10-14, the EV2 guardrails mask secrets in what **tools return** (files read, RAG passages, web results) before they reach the model, in the CLI and the scheduler. Since 2026-10-17, the input filter ([ADR-0027](../decisions/0027-filtre-d-entree-par-regles.md)) also masks secrets **typed in the conversation**, before the model, the profile and the saved session (checked by `tests/test_cli_persistence.py`). | ⚠️ **Largely covered.** Only secrets matching the patterns are masked: an unnamed password ("mon mot de passe c'est hunter2") gets through. E-mails and card numbers typed on purpose are not masked on input (ADR-0027). |
| L4 | **Dangerous code execution** generated by the model (file deletion, data leak, attack on a third party). | French Criminal Code art. 323-1 ff. (attacks on automated data processing systems) if the tool is used to attack a third party; civil liability | Explicit confirmation before any `write`/`execute` action (tool gateway, ADR-0006); unattended (X5), these actions are always refused. Docker sandbox without network, read-only system, unprivileged user, memory and CPU limits ([ADR-0012](../decisions/0012-sandbox-docker-chromium.md)). EV4 adversarial tests. | ✅ **In place** in `main`. Known limit: the confirmation prompt shows the code without escaping control characters (EV4 PERM-15/16, [report](../securite/EV4-tests-adversariaux.md)). |
| L5 | **Wrong answers or incorrect code** presented as reliable (hallucinations). | General liability law; transparency on AI use | The terms of use say answers must be reviewed. EV1 (`sensai-eval`) scores answers and flags contradicted or unverifiable claims ([ADR-0019](../decisions/0019-evaluation-par-juge-llm.md)): a team tool, not a check of every answer. | ⚠️ **Partial.** |
| L6 | **Licences of models and libraries** not respected. | French Intellectual Property Code; Apache-2.0, MIT, MPL-2.0 licences | Chosen models under Apache-2.0, Ollama under MIT ([licences.md](licences.md)). | ✅ For current dependencies. ⚠️ Licence of `nemotron-3-nano` to check before use. |
| L7 | **The project has no licence.** Without a `LICENSE` file, nobody has the legal right to reuse the code, team members included after the project. | French Intellectual Property Code | None. | ❌ **Decision to take** by the team (see [licences.md](licences.md)). |
| L8 | **Terms of use of third-party APIs** (web search, third-party MCP server): quotas, ban on storing or redistributing results. | Each provider's terms | `web_search` reads **Bing**'s HTML page, without an API or agreement ([ADR-0014](../decisions/0014-moteur-de-recherche-bing.md)). No provider yet for the third-party MCP tool. | ⚠️ **Open.** Microsoft's terms in principle restrict automated access outside the API: acceptable for a teaching demo, to be reviewed by a lawyer before any commercial use. Also to handle when the third-party MCP tool is chosen ([dependances.md](../dependances.md)). |
| L9 | **Transparency on AI.** Users must know they are dealing with an AI system. | EU AI Act (EU 2024/1689), art. 50 | The product presents itself as an AI assistant in the CLI. | ✅ Obvious by nature for a coding assistant. To be restated in the web interface. A development assistant is not among the "high-risk" uses of Annex III. |
| L10 | **Share links readable without authentication.** `POST /api/sessions/{id}/share` creates a read-only copy of a conversation (user and assistant messages) at `/share/<token>`, readable **without the access token** by anyone who can reach `sensai-web` and has the link, for **7 days**. Deleting the conversation does not revoke its links: the copy stays in `shares.json` until expiry or revocation. | GDPR art. 5(1)(f) and art. 32, only if the conversation contains personal data of other people (names, e-mails, client code) | Server bound to `127.0.0.1` by default (a `--bind` elsewhere prints a warning). Token from `secrets.token_urlsafe(32)`, only its SHA-256 stored. Snapshot passed through the EV2 output filter (`filter_output`). Page with all text escaped, no scripts (CSP `default-src 'none'`), `noindex`, `no-referrer`, `no-store`. Unknown, revoked and expired links give the same 404. File `shares.json` in mode `600`; expired links purged at server start ([ADR-0048](../decisions/0048-share-links.md), [donnees-locales.md](donnees-locales.md)). | ⚠️ **Partial.** Secrets are masked only when they match the EV2 patterns; other personal data is copied as is. Revocation exists only through the API (`POST /api/shares/<token>/revoke`), there is no button in the interface yet. Whoever has the link and network access to the server can read it until it expires. |
| L11 | **Deleted conversations remain in the SQLite file.** Deleting a conversation from the chat sidebar runs a `DELETE` without `VACUUM` (`SessionStore.delete`, `src/sensai/knowledge/memory.py`): the deleted text stays readable in the free pages of `sessions.db` with forensic tools. | GDPR art. 17 (erasure) applies to a controller holding someone else's data; for a single user's own data on their own machine, this is a security point (art. 32) more than a rights issue | The file is in mode `600` in a `700` folder. The retention purge (`SessionStore.purge`, run at server and CLI start) runs a `VACUUM` when it deletes at least one session, which rewrites the file. | ✅ **Fixed on 2026-10-29**: `SessionStore.delete` now runs `VACUUM` (`_vacuum()`, shared with `purge`); test `tests/knowledge/test_memory.py::test_supprimer_une_session_efface_aussi_son_texte_du_fichier` checks the deleted text is no longer in the file bytes. Before: ⚠️ accepted limit. Between a deletion and the next purge that removes a session, the text is still on disk. Fix: run `VACUUM` (or `PRAGMA secure_delete=ON`) after `delete`, at the cost of rewriting the whole file each time; workaround: `sqlite3 ~/.sensai/sessions.db VACUUM`. |
| L12 | **Attached files sent to the model and saved.** In the web chat, attached text files (max 3, text extensions only) are read in the browser and put in code blocks **inside the message**: they go to the model (to the RunPod pod with a remote `--host`, see L1) and are saved in the session like any message. | GDPR art. 5(1)(c) (minimisation), only if the file holds personal data | Same path as a typed message: the input filter (ADR-0027) masks recognised secrets before the model and the saved session; message over 20,000 characters blocked before sending; PDF/docx not accepted in the web. | ⚠️ **Partial.** Same limits as L3: unrecognised secrets and personal data in the file are sent and stored. The user decides what to attach. |

The ADRs 0006 and 0007 cited here are in [decisions/](../decisions/README.md).

## What to do, by priority

1. **L2**: protect access to the pod before any demo on RunPod.
2. **L1**: write down the pod's region and cloud type. For a demo with real
   data, prefer a European region and Secure Cloud.
3. **L7**: choose a licence for the project.
4. **L10**: add a revoke button to the interface, and revoke the links of a
   conversation when it is deleted.
5. **L11**: `VACUUM` after a deletion (or `secure_delete`). Done on 2026-10-29.
6. **L3**: done for recognised secrets (ADR-0027); secrets without a
   recognisable shape remain the limit, to be reminded to users.
